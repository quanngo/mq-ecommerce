Produce a fast orientation report for a developer who just opened this
workspace. Ground everything strictly in files you actually read — never
invent endpoints, schema, or architecture details that aren't present in the
source. If something is missing, say so plainly instead of guessing.

## Steps

1. **Read `projects.env`** at the workspace root. Enumerate every
   `FRONTEND_KEY_*`/`FRONTEND_NAME_*`/`FRONTEND_REPO_*`/`FRONTEND_START_*` and
   `BACKEND_KEY_*`/`BACKEND_NAME_*`/`BACKEND_REPO_*`/`BACKEND_START_*` entry
   (indexed 1..`FRONTEND_COUNT` / 1..`BACKEND_COUNT`).

2. **Check for a root `CLAUDE.md`.**
   - If it exists, read it — it's the pre-synthesized architecture overview
     generated by `./setup.sh` (step 3) and should anchor your summary.
   - If it doesn't exist, note that `./setup.sh` hasn't been run yet (or no
     projects are cloned) and build the summary from the per-project files
     instead (step 3).

3. **For each project from `projects.env`**, check
   `workspace/<type>/<key>/CLAUDE.md` (`<type>` is `frontend` or `backend`):
   - If it exists, read it and pull out: purpose, tech stack, key
     APIs/endpoints (backend) or key routes/pages (frontend), a short DB
     schema summary (backend), and any notable conventions.
   - If `workspace/<type>/<key>/` doesn't exist yet, or exists but has no
     `CLAUDE.md`, say so explicitly for that project and recommend running
     `./setup.sh`.

4. **Also check `.claude/rules/`** for any house-convention docs beyond the
   placeholder `README.md`, and mention/link them if present.

5. **Write the report** with this structure:
   - **Overview** — one paragraph on what the overall system does and how the
     frontend(s) and backend(s) relate, based on what root `CLAUDE.md` (or the
     per-project docs) actually say.
   - **Projects table** — columns: key | type | name | tech stack | one-line
     purpose | start command (from `projects.env`).
   - **Integration points** — how the frontend(s) talk to the backend(s):
     base URLs, auth mechanism, key shared contracts — only if stated in the
     source docs; otherwise state that it isn't documented yet.
   - **Where to go deeper** — links to the root `CLAUDE.md`, each project's
     `CLAUDE.md`, and anything found under `.claude/rules/`.
   - **Quick start** — `./setup.sh` if any project is missing/uncloned or
     lacks a `CLAUDE.md`; `./start.sh`, `./start.sh frontend`,
     `./start.sh backend`, or `./start.sh <key>` to run things, per the root
     `README.md`.
